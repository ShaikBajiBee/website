ChronosMatch: Zero-Copy High-Frequency Trading Engine

Candidate: Shaik Baji Bee (Data Associate L1. Intern) | Ref No: ITS/PY/1126 | Company: Infotact Solutions

1. Introduction & Objectives

ChronosMatch is a low-latency electronic trading engine built in Python. It replaces standard heap object allocations with a contiguous binary ring buffer to achieve deterministic microsecond execution for BUY and SELL orders while persisting order and trade history to an ACID-compliant SQLite database.

2. Zero-Copy Architecture Specification

Standard Python applications allocate memory dynamically on the heap for every dictionary or object. Under heavy order bursts, this triggers Stop-The-World Garbage Collector (GC) scans that degrade system responsiveness.

ChronosMatch utilizes a pre-allocated 3.2 Megabyte contiguous buffer (100,000 slots of 32 bytes each) sliced using Python's native memoryview and packed via struct.Struct('<cc2sQdIQ'):

Field Type Size Purpose
sidechar1 Byte'B' for Buy, 'S' for Sell
order_typechar1 Byte'L' for Limit, 'M' for Market
padding2 bytes2 Bytes32-byte cache alignment
order_iduint648 BytesUnique sequential order identifier
pricedouble8 BytesLimit order price
quantityuint324 BytesNumber of shares/contracts
timestamp_nsuint648 BytesHardware nanosecond timestamp

3. Matching Engine & Priority Logic

  • Price Priority: High bids execute before low bids; low asks execute before high asks.
  • Time Priority (FIFO): At identical price levels, earlier orders take precedence.
  • Execution Price: Matches occur at the resting limit order price (passive maker price).
  • Lifecycle: Orders transition from OPEN → PARTIALLY_FILLED → FILLED or CANCELLED.
